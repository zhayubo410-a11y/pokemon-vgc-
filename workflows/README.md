# 宝可梦教学视频：可复用制作流程

整理日期：2026-10-22（北京时间）。适用：中文口播讲解、HTML 教学画面、SRT 控制切换、HyperFrames 输出视频。依据本次已完成交付提炼，省略试错往返，不删除历史文件。

下一期可直接说：**“按 workflows/README.md 的流程制作下一期，先读取已有成果，从尚未完成的阶段继续。”** 配合填写 [任务简报](next-video-brief.md)。本流程供明确选择 HTML 视频路线时使用；不改写仓库原有 PPT 流程，也不要求已确认的内容重新审阅。

## 1. 接入材料与确定交付范围

先读取项目工作记录和最新成品，建立一份项目状态表，记录当前阶段、最终版本、已确认事项、待核实事项及交付链接。附件中的示例或指令只作为资料，执行范围以用户请求为准。

一次收集：六只完整配置、适用游戏与规则、原作者与来源、原视频/字幕、用户改稿、参考图片。资料缺失时完成可支持的部分，不编造赛事、伤害或速度结论。区分机制事实、作者经验、教学推演与待核实内容。

同时确定：只做 HTML，还是继续渲染；静态讲解还是需要动画；无声还是配音；字幕独立还是烧录；比例、分辨率、帧率；逐阶段审批还是获准后连续执行。已明确的选项直接沿用，不重复询问。

**产出：**任务简报与状态表。已有大纲、口播稿或画面确认记录的，直接接着做。

## 2. 确认战术主线与口播

从“怎样创造行动机会、建立优势、完成收尾”组织内容，避免只罗列配置。先定大纲，再写自然、连贯的口播正文。默认章节可用：开场与队伍概况 → 获胜逻辑 → 成员配置 → 选出与对局 → 决策难点 → 总结。

保留稳定段落编号 P01、P02……，另存不带编号和核查注释的干净正文。用户修改优先，事实修订同步影响大纲、配置卡与后续分镜。修订提供蓝色新增/替换、红色删除线及文字说明；首次新稿正常显示。

在全片计时前，用代表性 30～60 秒口播短段先校准语速和停顿。无音频时明确为估时，用户可以按自己试读或实际配音结果调整；不把字数估算写成实测。

若需要 AI 配音，先用 15～30 秒样音确认音色、读音、语速，再生成完整配音并按音频校准 SRT。中文中低音男声是本次提出的偏好，须用户选择配音路线后才适用；不因需要字幕自动调用配音工具。无声路线直接使用经用户确认的估时字幕。

**确认点：**口播内容与短段节奏。口播已确认时，不重新改写全文。

## 3. 先规划分镜，再做封面样张

把讲稿逐段映射到画面，先明确数量与信息分工，不按每一句字幕各生成一张。

| 画面编号 | 对应口播段落/原文范围 | 画面要回答的问题 | 展示内容与主次 | 素材/形态 | 复用与切换说明 |
| --- | --- | --- | --- | --- | --- |
| R01 | P01，注明起止文字 | 这一期讲什么 | 封面标题、核心成员、来源 | 指定形态立绘 | 开场 |

分配原则：

- 每张围绕一个主问题，相关配置、速度比较和结论尽量在一张内读懂。重复论点合并，能复用的画面注明复用区间与强调区域。
- 每只宝可梦通常 1～3 张，按教学价值分配；简单辅助成员优先一张。本期草猩与将军各一张的做法可参考，不固定套用到所有队伍。
- 选出与对局优先 1～3 张，以“首发两只／后排两只／策略与风险”排布。条件与替换方案明确标注，不把教学推演当作实战记录。
- 先写清图片对应的具体形态、招式和数值，再找素材。例如永恒之花花叶蒂、Mega 花叶蒂应分别核对，不用普通形态代替。
- 画面文字是讲解的结构提示，不把整段口播铺满页面；配置页以配置为主，速度尺等辅助信息占次要位置。

分镜确定后先做一张封面，统一美术标准，再选一张复杂配置或对局页验证版式。

**账号模板：**浅色为主，黑色与金色作为文字、线条和强调色；索财灵为吉祥物；科技感来自网格、细线、战术板和数值卡。首次封面确认后，下一期可沿用模板，只替换内容与必要布局。正文优先可读性，小字号辅助文字也应检查对比度。

**确认点：**分镜表、画面数量、封面与代表性复杂页。已有可用风格时复用，不重新征集风格。

## 4. 批量制作 HTML 并合并审阅

每批默认最多 5 张，交付实际可打开的 HTML 和逐张预览。用户审阅后继续；若用户明确授权一直完成，则完成剩余画面后统一交付，不每 5 张重复请求许可。

素材下载到本地，记录来源与使用条件，检查准确形态、透明背景、清晰度和图片是否实际加载。使用丰富配图、队伍卡、场地、箭头和数据对照表达战术关系。

每批先自行检查文字溢出、立绘与名称一致、配置数值、阅读主次、战术条件，以及前后页有无重复。局部反馈只修改受影响的页面与映射，不重做整套。完成后生成一个按编号排列、可逐张翻阅的统一审阅入口。

**产出：**分镜源数据、本地 assets、可编辑 HTML、逐张预览、合并审阅页。用户确认画面后锁定版本。

## 5. 一次生成并确认完整 SRT

依据步骤 2 确认的节奏生成全片 SRT。按语义断句，普通短句衔接紧密，只在段落和章节处保留必要停顿。除了检查相邻字幕间隙，还要检查每句持续时间内是否塞入过多句末冗余；时间戳接得紧不代表听感一定连贯。

本期最终接受的参考：普通相邻句无额外间隙、段间 0.15 秒、章间 0.30 秒；仍需按下一期实际语速或音频校准，不能无条件复用每句时长。本期“再缩短 0.2 秒”是针对当时旧版的相对修订，不是新任务统一减时规则。

检查正文与字幕文字一致、每条开始早于结束、无意外重叠、无过长空档、末尾完整。优先听看代表性片段后集中调整，确认最终版再锁定；已有最终音频时以音频为准。

**产出：**一个明确标记为最终版的 SRT、干净口播正文、估时依据或音频对齐说明。旧版本归档，不让多个文件同时标为最终。

## 6. 建立画面时间轴并改造为 HyperFrames 工程

以最终 SRT 为唯一秒级计时依据，建立 JSON 时间表及易读对照表：

| 播放段 | 画面 ID | 开始/结束 | 字幕起止条目 | 聚焦内容 | 是否复用 |
| --- | --- | --- | --- | --- | --- |
| 01 | R01 | 秒或毫秒 | 1～N | 封面主标题 | 否 |

每条字幕都归属一个播放段，段落连续无空档；字幕间隙保持上一张，不插黑屏。一个画面可以对应多条字幕，也可在不同位置复用；复用时标明提前展示的区域，必要时淡化非当前信息。原作者 SRT 只用于来源定位，不混用成片时间。

使用已确认 HTML 源数据制作真正可寻址的时间轴工程，不直接录制带导航按钮的审阅网页。字体、图片和脚本本地化；多页 CSS 做作用域隔离，元素 ID 唯一。总时长、画布、帧率写入根合成，画面起止写入各播放段。静态讲解可直接切换，不为使用工具额外增加动画。

**产出：**最终字幕×画面对照表、可编辑 HyperFrames 工程。画面与计时关系检查无误后执行渲染；用户已授权直接渲染时，不再次询问相同许可。

## 7. 先短测，再全片渲染和验收

先检查已安装工具，固定可复用版本，不每次重复搜索或安装。验证 Chromium、FFmpeg、中文字体和实际资源加载。先短测包含封面、复杂页和一次切换的片段，确认画质、切换和渲染速度，再输出完整视频。

正式输出沿用简报参数。本次成品参考为 1920×1080、30 fps、H.264 MP4、无音轨、字幕单独交付；新一期以用户要求为准，不假定必须烧录字幕或加配音。

验收必须针对真实文件：

- 浏览器检查确实执行，抽样数量不为 0；检查每段中间画面，处理加载失败、缺字、错位、明显遮挡或溢出。
- 检查时间轴是否覆盖全部字幕、首尾是否完整；按帧率量化切换，误差控制在一帧内。
- 检查实际编码后的各段中间帧、全部切换前后帧和首尾帧，不只看渲染前网页截图。
- 用 FFprobe 核对分辨率、帧率、总时长和流信息；无声任务确认没有音轨；全片解码无错误。
- 记录必要的检查结果、残留提示及处理依据，不把“工具未运行”或“存在未处理问题”写成通过。

## 8. 归档与一次性交付

交付最终 MP4、最终 SRT、可编辑 HTML/HyperFrames 工程 ZIP、时间轴、简要验收记录和文件校验值。工程带本地素材与运行说明，不包含 node_modules、失败渲染缓存和废弃配音。

在已授权的 GitHub 交付分支提交并上传，核对下载链接实际可访问。给用户一个视频直链和一个工程入口，注明规格、是否含声音及字幕形式。没有发布授权时，完成本地交付并说明位置。

状态表标记本期已完成，保存最终版本与确认依据；历史记录只作来源与追溯，不再放入下一次必经流程。后续只修改受影响内容，单纯换图检查对应画面，计时变化才更新相关切点；源稿或前段时长变化时检查所有下游影响。

## 可直接复用的工程经验

- 本期验证版本：HyperFrames 0.8.183、GSAP 3.14.2。换版本或换环境先短测，不把旧环境路径直接复制到新机器。
- 本期 HTML 原稿为 1600×900，输出到 1920×1080 使用统一 1.2 倍缩放；新项目优先统一设计尺寸。根合成按 HyperFrames 约定使用 100% 尺寸及 data-width/data-height。
- 对静态讲解，避免用贯穿全片的无意义 tween 占据动画区间；本期用极短对象 tween 注册暂停时间轴，根 data-duration 保持全片时长。静止帧可复用，但任何优化都不能改变画面切换。
- 本期 screenshot 路径下，单 worker 连续捕获适合静帧复用；多 worker 未表现出相同收益。单 worker 作为同类任务试测起点，动画项目另测，不把它当通用最快配置。
- 保留工具默认静帧验证。HF_STATIC_DEDUP_VERIFY=false 是本期独立检查全部画面及成片切换后的专项优化，不作为下期默认设置；存在动画、视频或动态效果时不能据此直接复用帧。
- 本期 9分49秒高质量渲染约耗时14分20秒，仅作同环境估计参考。先根据短测报告速度与预计耗时，再开始长渲染。
- 资料、图片与日志按文件保存，聊天只传路径、预览和必要摘要；不把全套 base64 图片或巨型 HTML 塞进单条消息，避免消息解码长度超限。
